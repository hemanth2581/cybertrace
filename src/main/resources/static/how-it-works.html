How CyberTrace Works

An intuitive 8-step walkthrough of our client-side storage + Java heuristic forensics architecture.

1
Step 1: Upload Raw CSV Audit Logs

The investigator uploads raw host/network CSV telemetry containing timestamps, user accounts, endpoint devices, source IPs, actions, file access events, and data transfer sizes.

2
Step 2: Parse & Validate Security Events in Java

Spring Boot's CsvProcessingService validates required headers (timestamp, user, device, ip, action) and parses raw stream data into normalized SecurityEvent objects.

3
Step 3: Analyze Activity & Threat Signatures

The Java engine checks IP subnets against RFC1918 ranges (10.x, 192.168.x, 172.16.x) to flag external rogue IPs and scans filenames for sensitive credentials (passwords.txt, credentials.txt, database.sql).

4
Step 4: Calculate Heuristic Risk Scores (0–100)

Deterministic penalty scoring is applied: Failed logins (+20), external IPs (+20), sensitive files (+20), data transfers ≥500MB (+15), privilege escalation (+10), and compound multi-vector penalties (+7).

5
Step 5: Synthesize Incident Dossiers (INC-001)

The IncidentService groups suspicious anomalies by targeted user, identifies attack classification (e.g. Account Compromise or Data Exfiltration), and compiles response recommendations.

6
Step 6: Reconstruct Forensic Attack Timeline

Events are sorted chronologically and the engine flags the FIRST SUSPICIOUS EVENT to clearly isolate initial infiltration points and lateral movements.

7
Step 7: Explore Correlated Evidence & Grounded Q&A

The UI maps the entity chain: USER → DEVICE → IP → FILE → DATA TRANSFER. The deterministic AI investigator answers questions strictly grounded in verifiable evidence without cloud AI.

8
Step 8: Export Official PDF Incident Report

With a single click, Spring Boot's PdfReportService compiles an official, publication-ready Digital Forensics Incident Report PDF directly to your device.
